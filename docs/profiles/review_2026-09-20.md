# Raster coverage and Peirce classification: Teensy A/B measurements

Measured 2026-09-20 using isolated candidate commits. Vertical coverage, pole classification and horizon interiors landed as `9080b04ef`, `e91e74d82` and `13c9cf4d4`. The measured baseline is `d9a39abd8cd69fc6ed91175a6e0398e0d71be961`.

All captures use Teensy 4.0 at 600 MHz, `POVSegmented<288,4,480>`, segment 0, live flywheel/DMA interrupts, and the supported device-locking `profile_one.sh` wrapper. Shipping means `-Os` with the landed selective-O3 regions; global O3 is the single-effect reference.

## Measured render cost

Positive changes mean slower rendering. Each candidate is compared with the mean of its two same-board baseline captures. This midpoint is a descriptive reference, not a statistical drift correction. Each fix was profiled separately; the costs are not an additive prediction for the combined image. No cadence tier changed in these workloads.

IslamicStars compares the same frame indices and per-frame shape owners across all three captures. It includes builds, transitions, finished meshes, ripples, and fades. Two baselines and one candidate per configuration are limited repeat evidence. The many correlated frames are not independent statistical trials. The repeat spans above are observed differences, not confidence intervals or universal noise bounds.

## vertical antialias coverage

Candidate `09cdc400921e40b63120d423582c0e3186b3edb8` passes `max(0.05, 2*pi/W)` into the two face latitude-bound calculations. At shipping width 288 that margin remains 0.05 radians. Thus the measured difference is code-generation/setup cost; these captures do not measure the added raster work at widths below 126.

Outward row rounding covers the 96x20 case. A sweep of 11,800 faces found no omitted paintable samples there, with either host or device pole offset. A real 64x144/device-offset case loses 19 paintable samples; the candidate restores them. The broader 64x144 sweep restores all 18,441 omitted samples. These are finite correctness experiments, not performance measurements. The committed regression covers the actual witness and unchanged shipping bounds.

## Peirce pole classification

Candidate `bf4fa1223439ab092855f10b41259e1d2cd68cdb` makes the fast Peirce kernel match the general kernel when `abs(y)` rounds to one. A 768-sample native pole sweep changes 280 metadata mismatches to zero. ARM disassembly confirms the new check remains in both measured kernels.

No shipping Teensy roster effect currently uses this Peirce kernel; Shader is intentionally simulator-only. The isolated PeirceProbe diagnostic uses the existing composed-effect lifecycle and pullback raster, with camera, dodecahedral kaleidoscope, PeirceFastSquare, grid, edge fade and triadic palette. An identical metadata-dependent tint in both arms keeps edge classification observable. It measures a representative consumer, not production Shader firmware. Rare pole-cap hits in the device raster are not established.

The diagnostic instrumentation is separate commit `3156f636ff9c247370ee2bbfd861efbfa7d49aea` and is not part of the proposed production fix. [Full A/B/A comparison and profiles](review_20260920/peirce_pole_classification.md).

## near-horizon face interiors

Candidate `846c2e746d08aca7ef3d6b38fc07c9edc0d73726` removes the 0.01 cosine floor from both face-distance and raster culls. The baseline-failing regression restores a valid interior pixel at center cosine about 0.008 inside a tangent-plane square of radius greater than 100.

The floor changes behavior only above a gnomonic cull radius of about 99.995. Native full-cycle applicability runs at Trans Speed 1 and 4 found a maximum cull radius of 1.514215 and zero floor-active faces, including actual recipe builds and ripples. These IslamicStars captures therefore measure ordinary code-generation cost. They do not bound the extra work of rendering newly accepted pixels on extreme custom faces.

Both ARM raster kernels shrink by 20 bytes; their pixel-loop comparison instructions are unchanged but move in memory. Shipping also changes profiling-scope inlining. Disassembly alone cannot attribute the small timing differences to one cause.

## Method, validation and reproduction

- IslamicStars uses COM3, 16-frame windows, Trans Speed 4, and epoch 1920 revolutions (240 seconds). Initial baselines run 210 seconds; candidates and repeats run 150 seconds after the 111-second cycle was established. Every capture independently passes complete-cycle and no-epoch-reset checks. Trans Speed 4 changes build/ripple sampling as well as duration; it is accelerated choreography, not the default per-frame distribution.
- PeirceProbe uses COM4, 70 seconds and 32-frame windows. Its six arms share identical diagnostic target and parameters. Repeated baseline disassembly is identical within each configuration.
- All three candidates pass 87 native test groups with zero failures; one Clang-22-specific generator check is skipped with the installed Clang 23. Focused baseline-failing regressions and live clang-format 22.1.8 commit checks pass. Each capture also builds production Phantasm with profiling disabled.
- The combined production-only stack `13c9cf4d42a0c5906321e9c195c98e224cc1e731` also passes 87 native groups with the same one skip, a release-WASM build and the WASM runtime smoke test. It contains vertical coverage, pole classification and horizon interior fixes in that order, excluding the Peirce diagnostic target. All 307 CI-selected committed source blobs pass clang-format 22.1.8.
- Capture checks include correct effect/config headers, fresh frame numbering, monotonic windows, real render-minus-wait telemetry, cycle/wall agreement, clean source provenance, and retained ELF SHA-256 identities.
- The external reader preserves `MIXED-PARENT` scan counters omitted by the stock counter regex. Exact frame peaks/spills require no adapter. Duplicate and shared counters are not summed as exclusive phase costs. All scopes include interrupts; ISR wake already includes packing/submission.

The refreshed [shipping baseline](shipping/profile_islamicstars_teensy_2026-09-20.md) and [O3 baseline](O3/profile_islamicstars_teensy_2026-09-20.md) remain the ranked roster entries. Experimental results are kept separate.

Raw captures, ELF/map artifacts, build/environment logs, native evidence, analysis scripts and exact candidate patches used local capture locations outside the repository under `build/prof/review_20260920/`. The local `candidates/candidates.bundle` preserves the experimental commits with baseline `d9a39abd` as prerequisite. The per-capture provenance paths also resolve under `build/prof/artifacts/`. Full per-shape and repeat comparisons are in `build/prof/review_20260920/analysis/islamic-comparison.json`.

The committed reports preserve the measurements; the local captures and candidate bundle are not distributed with this repository. With the exact candidate commit available, reproduce an IslamicStars arm in an isolated tree and run each configuration with a unique output path:

```bash
HS_TEENSY_PORT=COM3 HS_PROFILE_TREE=<tree> HS_PROFILE_OUT=<unique-log> \
  bash tools/profile_one.sh IslamicStars profile 150 16 \
  '-D HS_PROFILE_TRANS_SPEED=4 -D HS_PROFILE_EPOCH_REVS=1920'
```

Repeat with `profile_o3`. The diagnostic Peirce profiles contain their additional target flag and reproduction command. All board access must continue through the locking wrapper.
