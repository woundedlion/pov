# Contributing

This repository holds the Holosphere engine and firmware; the browser simulator
lives in the sibling [daydream](https://github.com/woundedlion/daydream)
repository and is built and installed from here. Read `README.md` §2 and §9 first —
§2 describes the architecture, and the §9 file map is gated against the tracked tree.
[§8 Building and Testing](README.md#8-building-and-testing) has the commands for all three
targets: the Teensy firmware, the WASM module, and the native test suite.

## Licensing

`LICENSE` grants PolyForm Noncommercial 1.0.0 to everything outside `effects/`
except three named paths: `core/engine/effects_legacy.h` is
reserved like `effects/`; `core/math/projections.h` and
`core/vendor/FastNoiseLite.h` are MIT. All rights over `effects/` are reserved. Every
tracked C/C++ source carries the header its path is granted, and
`tools/license_check.py` gates that in CI. A new source file needs the header
before it lands; a new generated one needs its generator to emit it.

## Landing model

`master` is **fast-forward only**. `.githooks/reference-transaction` refuses any
non-fast-forward move of the ref, so a rewind needs a deliberate one-shot token
(the hook's header documents it). The workflow this enforces:

1. Branch in a worktree taken off the ref, never off a possibly-stale `HEAD`:
   `git worktree add <path> -b <branch> $(git rev-parse refs/heads/master)`.
2. Commit there. Never commit in someone else's tree, and never `cd` into a
   tree — pass `git -C <path>` so a stray working directory cannot commit in the
   wrong one.
3. Land by rebasing onto the live tip and merging fast-forward only:
   `git -C <main> merge --ff-only <branch>`. A refusal means a peer moved the ref
   or the main tree carries overlapping work; re-read the tip and rebase again.
   Never stash or discard another session's work to make a landing fit.

New commits always run the pre-commit hook. Replaying commits that already
passed it — a cherry-pick, a rebase, or a series regenerated by committing
already-checked content — may skip the per-commit hook with `--no-verify`.
Before a series lands, its tip must pass
`bash tools/commit_checks.sh <base>..<tip>`, with `<base>` the master commit it
lands on. That runs the hook's checks once over the series' net change, plus
the whole-tree documentation, build-pin and lint checks the hook leaves out,
reading every file as of `<tip>`.

One logical change is one commit, with an imperative subject naming the
component (`scan: clamp the row index before the cast`).

Quoted first-party includes use repository-root paths, such as
`#include "core/math/3dmath.h"`. The repository root is the sole first-party
include directory; generated build headers use their build directory.
`tools/include_paths.py` also checks dependency direction: `core/` excludes
`effects/`, `targets/`, `workbench/`, `hardware/`, `tests/` and `tools/`;
`hardware/` excludes `effects/`, `targets/`, `workbench/` and `tests/`;
`effects/` excludes `targets/`, `workbench/`, `hardware/` and `tests/`;
`workbench/` excludes `effects/` and `targets/`. `core/pattern/` excludes
`core/color/`, `core/render/`, `core/control/` and `core/animation/`.
`FORBIDDEN_PREFIXES` in `tools/include_paths.py` also defines file-specific
layers for pattern and color modulation headers. Vendored core code and
`core/engine/effects_legacy.h` are exempt from direction checks. The first-party
`core/vendor/FastNoiseLite_config.h` follows the `core/` direction rules.
The profiling headers `tools/pc_sampler.h`, `tools/profile_isr_window.h` and
`tools/profile_clock.h`,
plus `tools/phantasm.ld`, follow the
`hardware/` direction rules. Linker imports use GNU ld `INCLUDE` syntax.

Use `HS_FLASH_MEMBER` for internal cold inline, template and COMDAT functions.
`HS_COLD_MEMBER` is an alias of `HS_FLASH_MEMBER`. `HS_ITCM_MEMBER` marks a
non-inlined function kept in ITCM at the translation unit's optimization; on
host it expands to nothing, unlike `HS_NOINLINE_NOCLONE`.

Before landing a refactor, search the old identifiers and behavior wording
across source comments and maintained documentation with `rg -n -i -F --
'old behavior phrase' .`. Read each match and correct stale contracts in the
same commit. Repeat the search after editing. For wording that should disappear
entirely, `python tools/docs_check.py --skip-checkout daydream --retired-term
'old behavior phrase'` rejects remaining matches in tracked text; repeat
`--retired-term` for each phrase. Review any accurate historical references
separately. The normal documentation gate still checks paths and counts.

## Comments

A comment records what a reader cannot get from the code. A cost, error bound,
threshold or count stated in a comment needs a `static_assert` or test beside it
that pins the figure; otherwise state the property without the number. Name
code by its symbol in backticks; `tools/docs_check.py` fails when a backticked
symbol or path in a C/C++ source comment no longer exists.

A test's name and brief state the one behaviour it asserts, in one line; a
file or suite header states its purpose, not an inventory of its cases. Update
both when the assertions change.

## Design specs

[The specifications index](docs/specs/README.md) lists the design contracts
that span several files. A change that moves such a contract carries the
corresponding spec update with it.

A change that stays inside one file needs no spec. A new subsystem other code
will be written against does: land the spec with the implementation, not after
it.

## Gates

Host tooling and Git hooks require Python 3.11 or newer. Set `HS_PYTHON` to
select a supported interpreter; CI uses the version pinned in `tools/build_pins.py`.
Install the combined host tool locks with
`python -m pip install --require-hashes -r requirements/dev.txt`;
`just setup` repeats that install, verifies Node, and installs this repository's
npm dependencies. Ninja, Emscripten and the firmware toolchain remain separate
prerequisites for their respective targets.

The engine CI gates run in `.github/workflows/ci.yml` behind the aggregate
`CI green` check. Local hooks and the sibling simulator checks below have
separate entry points. `.githooks/pre-commit` is a fast prefilter over the staged
files — format, lint, license headers, include paths and encoding; the
protected branch's `CI green` status is the authoritative correctness gate.

- **`.githooks/pre-commit`** — rejects staged whitespace errors, checks staged
  first-party C++ with clang-format, and runs ruff/eslint/shellcheck on staged
  sources with the staged lint configuration. It then runs
  `tools/license_check.py`, `tools/include_paths.py` and
  `tools/encoding_check.py` with `--staged`, over the staged content of the
  staged files only, so the verdict is on what is being committed rather than
  on the working tree. A required tool missing for an applicable change fails
  the commit rather than skipping the check. Configuring the `tests` preset
  points `core.hooksPath` at `.githooks` for you. Setting `core.hooksPath` also
  enables the post-commit size-trail capture, which can run Python and append
  to `teensy-size-trail.tsv` in the Git common directory.
- **`bash tools/commit_checks.sh <base>..<tip>`** — the hook's checks over a
  commit range's net change, plus the whole-tree checks the hook leaves out:
  `tools/docs_check.py` (without `--sync`), `tools/docs_images.py`,
  `tools/build_pins.py --check`, the whole-tree license, include and encoding
  checks, the whole-tree lint gate when `.clang-format`, `ruff.toml` or
  `eslint.config.mjs` changes, and, when the profile archive, its validator or
  its effect roster inputs change, the archive structure and coverage gate
  using the pinned Node version. Every file is read as of `<tip>`. It also
  fails when the range adds an `HS_CHECK` whose text the base lacks, unless a
  case in `tests/test_death.h` pins it or a `// no death case: <reason>`
  comment on its line or the line above waives it (a host-unreachable guard).
- **`.githooks/pre-push`** — checks new guards in each pushed range the same
  way, then runs `tools/local_ci.sh --commit` on each pushed ref's tip
  commit: every `ci.yml` job this machine can run, through the same
  `tools/ci/` scripts the workflow calls, each lane stopping at its first failure
  (the fast-math optimized flavour stays in CI: its bit patterns differ here),
  plus the local-only Windows suite. The optimized, WASM and firmware-warning
  jobs are manual (`bash tools/local_ci.sh --commit <sha> -- <job>...` runs
  named jobs in the dedicated worktree); the PCB and
  Python suites run only when the commit changes one of their inputs; and the
  native, Python and PCB jobs run as lanes beside the others, their build and
  worker fan-out capped. `bash tools/local_ci.sh
  --list` prints each job's local runner or the reason it cannot run locally,
  and `--check` fails when a `ci.yml` job has neither.
  It runs in a dedicated worktree beside the checkout
  (`../temp/<repo>-local-ci`, or `HS_LOCAL_CI_DIR`) whose build trees persist,
  so peers' uncommitted work cannot affect the verdict; one run holds the lock
  at a time. Only full runs read and write the passed-commit record; named
  jobs always run. Missing PlatformIO libdeps environments are copied from
  the main checkout. Tools that are
  not on `PATH`, such as the pinned Doxygen and Graphviz, are added with
  `git config --add hs.localCiPath <dir>`; the sibling `../emsdk` and
  `../daydream` checkouts are found automatically. A full run takes tens of
  minutes, so push from a terminal or a background task.
- **Shell edits:** the pre-commit hook runs `shellcheck -x` on staged `.sh` files and `.githooks/` scripts. Install its pinned prerequisite with `pip install --require-hashes -r requirements/shellcheck.txt`.
- **clang-format is pinned to 22.1.8.** A different major reflows unrelated
  code, so the hook fails rather than trusting an off-major verdict. Install the
  pin (`pip install --require-hashes -r requirements/clang-format.txt`) or
  point `CLANG_FORMAT` at a `clang-format-22` binary reporting that exact
  version. Every external tool version is single-sourced
  through `tools/build_pins.py`, whose `--check` fails a partial bump.
- **Guard tests:** Prove that a valid companion fixture is accepted. For the
  guarded fixture, assert the intended result or diagnostic. Deleting the
  guarded line must fail the test; an unrelated rejection cannot satisfy it.
- **Behavioral tests:** For every new or strengthened test, name a concrete
  mutation of production code that must make it fail. Use an independent
  expected result and assert the observable effect before a helper can perform
  the behavior being tested. Exercise that mutation when practical, restore the
  production code, and record the mutation and observed result in the change's
  validation notes. A test that stays green needs a stronger assertion.
- **Native suite.** `just test` sets CI's `HS_SMOKE_FRAMES=120`,
  `HS_SKIPS_ARE_ERRORS=1` and `HS_BUFFER_FREE_WATCHDOG_US=30000000`.
  Set `HS_EFFECTS_FULL=1` to run the full-resolution leg locally. For a
  targeted run with the defaults, use
  `cmake --preset tests && cmake --build --preset tests`,
  `cmake --build --preset tests --target excluded_targets`, then
  `ctest --preset tests`. The 8-frame smoke default runs too briefly for a
  preset transition to arm.
- **Render no-op proof:** a refactor or performance change that should not
  move any pixel runs `bash tools/render_diff.sh <base>`, which builds `<base>`
  in a dedicated worktree and compares its render hashes with the working
  tree's build. Nothing is committed; the filter-pipeline effects assert
  properties instead of recorded hashes. The `render_hashes` module hashes
  every roster effect at every preset at 96×20 with the simulator's load
  settings; `bash tools/render_diff.sh --report <base>` builds only that
  module (`test_render_hashes`) and lists the changed renders per effect
  (`AlienBrain p0-p3`). The non-blocking `render-hash-report` CI job runs that
  report against the push's previous tip or the pull request's base and
  writes it to the job summary.
- **Approximation captures:** the fast Peirce framebuffer oracle keeps preset 4's
  restored projection, field and palette path, with hue-modulation amounts set to
  zero before preparation. Its 256-code ceiling isolates projection error; it
  does not bound the authored preset's final hue-shifted color. The full production
  hue oracle retains its separate 3066-code ceiling. Native and WASM capture
  producers also report the authored-hue Peirce comparison as a coupled diagnostic:
  a small projection perturbation can cross the canonical gamut mapping's
  discontinuity. These diagnostics have no isolated projection pass/fail claim.
- **Node script suite:** `npm test` runs every `scripts/*.test.mjs` — the
  shader-workbench schema and digest contracts, the WASM smoke predicates, the
  engine bindings contract, the profile roster and the PNG probe. CI runs it as
  its own `scripts-unit-tests` job. Set `HS_BROWSER_TESTS=1` when running
  `node --test scripts/screenshot_resolution.test.mjs scripts/png_probe.test.mjs`
  to include the Chromium capture-descent and PNG-decoder parity tests; first run `npm ci` and `npx playwright install chromium`.
- **Native variants and coverage:** `sanitizers` runs the whole suite under
  ASan and UBSan. `thread-sanitizer` runs the concurrency modules under TSan,
  compiles the targets excluded from the default build and runs plot/scan at
  the physical display profile. `optimized-tests` runs the optimized flavours,
  including the death harness with `NDEBUG`. `code-coverage` enforces aggregate
  and directory coverage and runs the generated-table pins. The Windows suite
  runs only in the pre-push local CI (`tools/local_ci.sh`).
- **Generated-source provenance:** `lut-provenance`, `reaction-graph-provenance`,
  `gamut-lut-provenance`, `srgb-decode-provenance` and `patterns-provenance`
  regenerate their artifacts and compare them with committed bytes. Change the
  generator or authored input and regenerate; hand-editing its output fails.
- **Firmware:** `teensy-size` enforces firmware memory and layout budgets, and
  `teensy-warnings` checks every PlatformIO environment with the pinned toolchain.
  Its cold capture also covers composed profiling knobs, PC sampling and
  plot-stall attribution configurations.
  The warning gate includes source diagnostics and fileless C compiler, C++
  compiler, linker and command-line diagnostics. C++-only options stay in
  `CXXFLAGS`; shared build flags must also be valid for C sources.
  For an archived capture from another checkout, pass that checkout's
  `--platformio-ini` path so absolute diagnostics use its repository root.
  The local entry points are `just teensy-size` and `just teensy-warnings`.
- **Published artifacts:** `wasm` builds and verifies the engine bundle;
  `screenshot-gallery` checks capture membership and images. `docs-doxygen`
  builds the API reference with warnings treated as errors. These complement
  the Markdown and image-reference checks below.
  Local Doxygen recipes and the coverage gate use the selected Python
  interpreter for the linker-script filter, including `HS_PYTHON` in `just`.
- **Host-Python tool suites:** `just python-test` and the CI `python-tests`
  job run `python tools/run_python_tests.py` across all tracked Python suites,
  including firmware gates, profiling tools, build checks and PCB generators.
  It rejects empty suites and propagates failures. `just python-ci` matches the
  CI job by also checking routed candidate status and provenance with
  `hardware/phantasm/gen/release.py check-candidates`, then routed PCB metadata
  with `hardware/phantasm/gen/board_metadata.py --check`. Install `requirements/numpy.txt`, `requirements/ruff.txt`,
  `requirements/shellcheck.txt` and `requirements/cmake.txt` first (the same set the CI job installs);
  no ARM toolchain or KiCad is required.
- **PCB:** `pcb-tests` runs the KiCad-backed generation, DRC, parity and
  fabrication suite (`python tools/run_python_tests.py --suite hardware/phantasm/gen/tests`)
  against pinned KiCad 10.0.4; locally it needs that KiCad install.
- **Lint:** `just lint` checks `just --fmt --check`, working-tree whitespace,
  invalid UTF-8 and reversible cp1252 mojibake in tracked text (`tools/encoding_check.py`),
  declared line endings, canonical first-party includes, Python selection and
  ruff, JavaScript selection and eslint, tracked shell files with shellcheck, the profiling roster, and
  actionlint last. CI applies the
  corresponding checks; the hook lints staged Python, JavaScript, and shell files.
- **Documentation:** the ci.yml docs-markdown job runs `tools/docs_check.py`
  without `--sync`: fences, links, anchors, every backticked repo path, every
  backticked symbol in a C/C++ comment, the README's file map against the
  tracked tree and its effect counts against `HS_EFFECT_LIST`. `just docs-sync` regenerates the maps and counts first,
  then runs the same checker, so the repaired diff lands with the change.
  `python tools/docs_images.py` resolves every documented `<img>` against the
  tracked tree. It only reports; `--stage` copies the images into a built
  Doxygen tree and is the sole mode that writes.
  `python tools/doc_coverage.py` (`just docs-coverage`; the ci.yml
  docs-doxygen job) fails on any Doxygen input symbol without a doc comment,
  any input file without an `@file` block, and any documented function
  missing an `@param` or `@return`. It exempts only defaulted or deleted
  members, assignment operators, container aliases, per-model
  `Pullback::Interp::Op` contract members, effect-spec overrides of
  `Pullback::Spec` fields, trait-specialization `Type` results, and macros
  the same file `#undef`s.
- **License headers:** `python tools/license_check.py`. The staged-tree
  pre-commit check and `just license-headers` run it; `just python-test` runs
  the checker's unit tests.
- **Simulator:** in the daydream checkout, `npm ci` then `npm test`; its
  `pre-push` hook runs lint, typecheck, the import-map and Tailwind stylesheet freshness
  checks, and three workflow helper tests. The full JavaScript suite is separate. daydream's deployment gate
  tests an immutable Holosphere/daydream pair before publishing; Holosphere CI
  does not run a daydream consumer job. See daydream's deployment documentation.

Outside the replay rule in [Landing model](#landing-model), `--no-verify` is
the explicit emergency escape from the local prefilter. It does not bypass
protected-branch CI.

## On-device uploads

Use `tools/profile_one.sh` for build, upload and capture under the shared
device lock. Its default uploader uses the verified headless TyTools release
when installed. Install the pinned Windows executable once with:

```sh
python tools/setup_teensy_uploader.py
```

The installer verifies the release archive and executable hashes, retains
the release license and records provenance under the user's .holosphere/tools
directory. Uploads verify the executable again; they do not download tools.
The version, official release URL and hashes are declared in
`tools/teensy_upload.py`.

Set `HS_TYCMD` to a native Windows executable path to select another copy of
the pinned tool. `HS_UPLOAD_BACKEND=headless` requires headless upload;
`HS_UPLOAD_BACKEND=vendor` explicitly selects the PlatformIO vendor uploader.
Without an installed headless tool the default remains the vendor uploader.
A selected tool's checksum, version or upload failure is reported without
silently switching uploaders.

The headless path resolves the lock's exact COM interface to one Teensy 4.0
serial number and USB location, then pins both identities through reboot and
upload. Missing or ambiguous matches fail. The claim token is checked again
before upload, tool calls have timeouts, RTC is preserved, and the selected
board and firmware hashes are printed with the tool provenance. The helper's
`--resolve` mode only verifies the tool; uploading requires the held claim.

## Reporting a vulnerability

Report privately through GitHub's security advisories for this repository
("Security" → "Report a vulnerability") rather than opening a public issue.
